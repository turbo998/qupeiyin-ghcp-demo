为什么是 GHCP:三个企业级硬理由

🏢

① 仓库感知 · Repo-Aware

Copilot 自动读取 .github/copilot-instructions.md,把公司规则倒灌进每次会话。

→ 不需要每次重写 system prompt

🔐

② 数据不出企业边界

SOC2 Type II + ISO 27001 + EU 数据驻留;代码和提示词都在 GitHub Enterprise 内。

→ 满足等保 · 满足合规审计

🔀

③ 多模型路由

Claude / GPT / Gemini 同一界面切换;模型不绑死,新模型上线无切换成本。

→ 旧推理留 GPT,代码主力 Claude

🏛️ GitHub Enterprise + Microsoft Azure 双重审计 · 每一次 Agent 操作都有 可追溯日志 + IAM 控制

6 个 Prompt 模板 = 团队最佳实践的可执行沉淀

每个 slash command 都是一份团队 SOP · 复制粘贴即用 · git 版本管理 · 全员复用

/design-feature
输入:一句业务需求
输出:ASCII 架构图 + API 表 + 数据模型 + 风险清单
/code-review
输入:PR diff
输出:行内评论 + 必改 / 建议改 / 表扬三档
/fix-bug
输入:错误日志 + 复现路径
输出:根因分析 + 补丁代码 + 回归测试
/investigate-issue
输入:线上事故 ticket
输出:5why 时间线 + 影响范围 + 改进项
/add-endpoint
输入:接口名 + 字段
输出:Controller + Service + Schema + OpenAPI 文档
/ship-release
输入:本周合并的 PR 列表
输出:CHANGELOG + Release Notes + 公告稿
🎓 新工程师入职第一周不再问"我们公司怎么写 PR 描述" · 直接 /ship-release · 老师傅离职,工艺不丢
